# Implementation decisions

1. This is an original procedural-art prototype. Reference screenshots guide composition and the cutaway view; no imagery is copied. One 64×64-tile room is positioned inside the central 2×2 chunks of a 4096 px world, with a neutral floor beyond it.
2. Character base, garment, headwear and prop sheets use actual Aseprite JSON-array files from the beginning. The importer restores trimmed frames to a full canvas before mirroring/compositing. The Lab and build share the same pure typed-array compositor; adapters only move the resulting pixels into canvas or sharp.
3. A 60-frame action map distributes each action's unique frames over the character loop. Holds are implicit equal-length intervals. Prayer uses eight art frames for four posture pairs and is explicitly flagged for panel review.
4. Content is seeded only when absent. Existing part sheets are preserved on subsequent generator runs. The PRNG is build-time-only, with seed 796. The optional worshipper variant has its own serialized seed and resolves before validation. Runtime simulation contains no PRNG or wall-clock reads.
5. A later person's exact full-name exception does not exempt another occurrence of the same given name. Lineage tokens are excluded after the first ibn/bin/bint separator; exact full identities and given-name tokens are checked. Umar ibn Abd al-Aziz and Fatima al-Fihri are intentionally allowed. No panel approvals are fabricated.
6. All sample named cards remain unapproved and unresearched. Consequently `pnpm build` must fail. `pnpm build:preview` is explicitly a draft review artifact; it is not an approved release.
7. Camera URL x/y values describe the world centre, not screen offsets. The shared `screenToWorld` helper takes explicit screen offsets. The minimap uses the eighth-scale full-scene image. Mobile prioritises world controls and bottom-sheet stories; its minimap is hidden at narrow widths.
8. Multi-tile object strips calculate depth at the front boundary of the footprint for each screen-x slice. Source shadows are baked; elevated characters have separate baked shadow sprites that stay on the floor. Dynamic hit masks use the actual trimmed alpha bitset. Full-scene LODs share the same baked frames and depth values as live rendering.
9. WebGL is the runtime target. Pixel scale mode is nearest, canvas resolution is one CSS pixel, camera offsets are rounded, and the canvas is styled pixelated. This deliberately uses CSS/world pixels rather than DPR supersampling, keeping the same crisp pixel lattice on retina screens. Physical Android performance has not been measured.
10. Engine input, sprites and camera are framework-independent. React controls the typed Engine API and Zustand owns language, motion, selection and camera UI state. Inspector and Lab are development only; the static review build omits their navigation/routes.
11. Source English, Arabic and Bangla UI dictionaries are bundled to avoid language-switch requests. Font loading is optional and falls back to system fonts; translations await human proofreading. Historical prose and sources remain plainly labelled placeholders.
12. The developer overlay reports actual ticker FPS, visible characters and instrumented WebGL draw calls. Performance targets require a real mobile-device profiling pass before a release claim.
13. Setup uses the existing isolated checkout. Native build scripts are allowed only for sharp and esbuild. `maxrects-packer` is pinned to 2.7.3 because the registry marks 2.7.4 as having broken entry points.

14. Following the screenshot feedback, the initial view is a scene-first 2× close-up with no introduction panel covering the world. The lighter stone palette, adjoining cutaway interiors, 48 additional neighbours, 230 objects, shelves and striped stalls follow the references’ density and layering. All art is still original procedural pixel art. Floor carpets and rugs are baked into background chunks so they cannot occlude characters. `refine-scene.ts` is an explicit art-refresh command; standard startup does not overwrite artist sheets.

15. Vercel’s hosting context is separate from content approval. Importing `main` creates a Vercel Production deployment even while this project is a draft prototype. Therefore `build:vercel` defaults to a clearly labelled prototype on both Preview and Production URLs. The optional `DAR_CONTENT_MODE=approved` selects the strict `pnpm build` release path. All sample approval flags remain false; all denylist, depiction, wardrobe and script validation remains active.

28. The world is now a small planet (project owner's request). Content is still authored in tile space; `packages/shared/planet.ts` wraps it onto a sphere of radius 44 tiles with an azimuthal equidistant projection centred on tile (50, 30). That keeps scripts continuous, keeps distances from the centre, and stretches the map's far corners by at most about 30% tangentially. The camera keeps planet north up and views the focus point from 30° above its horizon, so near the focus the ground projects exactly like the old 2:1 isometric diamond and all existing object art stays correct. Billboards stand on the surface and lean outward toward the horizon (`lean` 0.5 keeps most of the disc upright). Sprites beyond the horizon are drawn behind the planet, so their tops peek over the edge.
29. The ground is drawn by a GLSL shader on a full-screen quad. It inverts the projection per pixel and samples a 16-texel-per-tile top-down texture made at build time from the isometric floor art. Elsewhere it draws grass, lakes and a ring road from `WILD`, and adds banded lighting, a limb tint and a halo drawn behind everything. Chunk backgrounds and LOD stills are gone. The minimap uses the ground texture, with the camera focus as a dot. The build plants about 700 trees on the rest of the globe (jittered Fibonacci lattice, avoiding lakes and the road). Multi-tile objects keep their 16 px strips; each strip rests on its own footprint front point, so long walls bend with the curve.
30. Because the camera decides which side of a character is seen, every action is baked in all four facings, and the engine picks SE/SW/NE/NW from the projected world direction. `back` characters are restricted to NE/NW at runtime too. This roughly doubles baked frames (two 2048² atlases).
